1 · Dados

O problema: dentro ou fora do círculo?

N = 2000
X = torch.rand(N, 2) * 4 - 2   # pontos em [-2, 2]²
y = (X.pow(2).sum(dim=1) < 1.5).long()
X.shape = [2000, 2]y.shape = [2000]y ∈ {0, 1}

Cada ponto tem 2 coordenadas. O rótulo é 1 se x² + y² < 1,5 (laranja) e 0 caso contrário.

Nenhuma reta separa as duas cores. Por isso precisamos de camadas escondidas com ativação não linear.

1 · Dados

Separar e servir em lotes

2000 pontos → 80% / 20%
treino · 1600
val · 400
1600 ÷ 64 = 25 lotes por época

O DataLoader entrega um lote de 64 pontos por vez. Uma época é passar pelos 25.

shuffle=True só no treino: embaralhar evita que a rede aprenda a ordem dos dados.

n_train = int(0.8 * N)
train_ds = TensorDataset(X[:n_train], y[:n_train])
val_ds   = TensorDataset(X[n_train:], y[n_train:])

train_dl = DataLoader(train_ds, batch_size=64,
                      shuffle=True)
val_dl   = DataLoader(val_ds, batch_size=256)

A validação usa dados que a rede nunca vê no treino. É ela que diz se o modelo generaliza.

1 · Dados · extra

Dataset customizado (map-style)

from torch.utils.data import Dataset

class CirculoDataset(Dataset):
    def __init__(self, n, raio2=1.5):
        self.X = torch.rand(n, 2) * 4 - 2
        self.y = (self.X.pow(2).sum(dim=1) < raio2).long()

    def __len__(self):           # quantas amostras?
        return len(self.X)

    def __getitem__(self, i):    # a amostra i
        return self.X[i], self.y[i]

O contrato são só dois métodos: __len__ e __getitem__. O DataLoader cuida do resto.

Quando usar

Dados em disco carregados sob demanda (uma imagem por vez), ou transformações por amostra, como data augmentation.

Exemplo de __getitem__ lendo do disco

img = Image.open(self.caminhos[i])
O arquivo só é aberto quando o índice é pedido.

Uso: DataLoader(CirculoDataset(2000), batch_size=64, shuffle=True)

1 · Dados · extra

Dividir, recortar e juntar datasets

from torch.utils.data import (
    random_split, Subset, ConcatDataset)

ds = CirculoDataset(2000)

train_ds, val_ds = random_split(
    ds, [0.8, 0.2],
    generator=torch.Generator().manual_seed(0))

primeiros = Subset(ds, range(100))
maior = ConcatDataset([ds, CirculoDataset(500)])

random_split

Divide aleatoriamente por frações ou tamanhos. O generator com semente torna a divisão reprodutível.

Subset

Uma “janela” sobre índices escolhidos. Ótimo para testar com poucos dados antes de treinar tudo.

ConcatDataset

Cola datasets em sequência. Aqui len(maior) == 2500.

Nenhum deles copia os dados: guardam só índices e referências.

1 · Dados · extra

IterableDataset: dados em fluxo

from torch.utils.data import IterableDataset

class CirculoStream(IterableDataset):
    def __iter__(self):
        while True:              # fluxo infinito
            x = torch.rand(2) * 4 - 2
            y = (x.pow(2).sum() < 1.5).long()
            yield x, y

dl = DataLoader(CirculoStream(), batch_size=64)
xb, yb = next(iter(dl))          # um lote

Em vez de __getitem__, implementa __iter__: não existe índice, as amostras simplesmente chegam em ordem.

Quando usar

Dados que não cabem na memória, arquivos lidos linha a linha, streams e logs.

Cuidados

shuffle=True gera erro. Com fluxo infinito, conte passos em vez de épocas. Com num_workers > 0, cada worker repete o fluxo: divida o trabalho com get_worker_info().

Sampler: equilibrar as classes

from torch.utils.data import WeightedRandomSampler

y_train = y[:n_train]
contagem = torch.bincount(y_train)     # [fora, dentro]
peso_classe = 1.0 / contagem.float()
pesos = peso_classe[y_train]           # 1 peso por amostra

sampler = WeightedRandomSampler(
    pesos, num_samples=len(pesos), replacement=True)

train_dl = DataLoader(train_ds, batch_size=64,
                      sampler=sampler)

No nosso círculo só uns 29% dos pontos estão dentro (área π·1,5 ÷ 16). A classe “fora” domina.

sem sampler (esperado)
fora 71%
29%
com WeightedRandomSampler (esperado)
fora 50%
dentro 50%

A classe rara é sorteada com mais frequência. sampler e shuffle=True não podem ser usados juntos.

Outras formas de amostra

Sequências de tamanhos diferentes

from torch.nn.utils.rnn import pad_sequence

def juntar(lote):
    seqs, ys = zip(*lote)
    xb = pad_sequence(seqs, batch_first=True)
    return xb, torch.tensor(ys)

dl = DataLoader(ds_textos, batch_size=32,

O collate padrão usa torch.stack, que falha se as formas diferem. Um collate_fn próprio completa com zeros até o maior tamanho do lote.

1 · Dados · varlen

O custo do padding

4 sequências · comprimentos [3, 7, 2, 5]

Para empilhar, o collate com padding completa tudo até a maior sequência do lote.

4 × 7 = 28 posições17 tokens reais11 vazias (39%)

A GPU calcula sobre as posições vazias do mesmo jeito. Com textos reais, de 20 a 4000 tokens, o desperdício pode passar da metade do lote.

E ainda é preciso mascarar: uma máscara de atenção para ignorar o padding e ignore_index=-100 na loss.

1 · Dados · varlen

Varlen: uma fila de tokens + cu_seqlens

x = torch.cat(seqs) · número = position_ids
def collate_varlen(lote):
    seqs, ys = zip(*lote)                  # seqs: [L_i, d]
    lens = torch.tensor([len(s) for s in seqs])
    x = torch.cat(seqs)                    # [sum(L_i), d]
    cu = F.pad(lens.cumsum(0), (1, 0)).int()  # [0,3,10,12,17]
    pos = torch.cat([torch.arange(L) for L in lens])
    return x, cu, int(lens.max()), pos, torch.tensor(ys)

Nenhum padding: o lote é 1 tensor achatado. A sequência i ocupa x[cu[i]:cu[i+1]].

position_ids recomeçam em 0 em cada sequência, e max_seqlen ajuda os kernels a dimensionar o trabalho.

1 · Dados · varlen

Lotes por orçamento de tokens

from torch.utils.data import Sampler

class TokenBudgetSampler(Sampler):
    def __init__(self, lens, max_tokens=4096):
        self.lens, self.max_tokens = lens, max_tokens

    def __iter__(self):
        ordem = torch.randperm(len(self.lens)).tolist()
        lote, total = [], 0
        for i in ordem:
            if lote and total + self.lens[i] > self.max_tokens:
                yield lote                 # lista de índices
                lote, total = [], 0
            lote.append(i)
            total += self.lens[i]
        if lote:
            yield lote

dl = DataLoader(ds, batch_sampler=TokenBudgetSampler(lens),
                collate_fn=collate_varlen)
cada lote: até 4096 tokens
lote 1
lote 2
lote 3

O número de sequências varia, mas o de tokens fica quase constante: memória e tempo por passo previsíveis.

batch_sampler devolve listas de índices e exclui batch_size, shuffle e sampler. Tire a média da loss por token, não por sequência.

1 · Dados · varlen

Atenção que não vaza entre sequências

Com tudo numa fila só, um token poderia “ver” outra sequência. A máscara correta é bloco-diagonal, e causal dentro de cada bloco.

from flash_attn import flash_attn_varlen_func

# q, k, v: [total_tokens, n_heads, head_dim]
out = flash_attn_varlen_func(
    q, k, v,
    cu_seqlens_q=cu, cu_seqlens_k=cu,
    max_seqlen_q=max_len, max_seqlen_k=max_len,
    causal=True)

O kernel lê cu e só calcula os blocos laranja: nenhuma operação é gasta nas áreas cinzas. Requer GPU e o pacote flash-attn.

1 · Dados · varlen

A mesma ideia em PyTorch puro: FlexAttention

from torch.nn.attention.flex_attention import (
    flex_attention, create_block_mask)

# a qual sequência pertence cada token: [0,0,0,1,1,...,3]
doc = torch.repeat_interleave(torch.arange(len(lens)), lens)

def doc_causal(b, h, q_idx, kv_idx):
    mesma_seq = doc[q_idx] == doc[kv_idx]
    return mesma_seq & (q_idx >= kv_idx)

T = len(doc)
mask = create_block_mask(doc_causal, None, None, T, T)
out = flex_attention(q, k, v, block_mask=mask)
# q, k, v: [1, n_heads, T, head_dim]

Você escreve a regra da máscara como uma função Python de (q_idx, kv_idx). O PyTorch compila um kernel que pula os blocos inteiramente mascarados.

doc[q] == doc[kv]

Só enxerga tokens da mesma sequência.

q_idx >= kv_idx

Só enxerga o passado (causal).

O lote empacotado vira “1 sequência longa” de T tokens. Disponível a partir do PyTorch 2.5.

Operações por sequência, sem padding

média por sequência (pooling)
B, d = len(lens), h.shape[1]      # h: [T, d]
seq_id = torch.repeat_interleave(
    torch.arange(B), lens)            # [T]
soma = torch.zeros(B, d).index_add_(0, seq_id, h)
media = soma / lens[:, None]          # [B, d]
nested tensors (jagged)
nt = torch.nested.nested_tensor(
    list(seqs), layout=torch.jagged)
nt.offsets()                          # = cu_seqlens

Camadas que agem token a token (Linear, MLP, LayerNorm) funcionam direto no tensor achatado [T, d]. Só o que mistura tokens precisa saber das fronteiras.

Padding

Simples e universal. Bom quando os comprimentos são parecidos.

Varlen

Zero desperdício. Padrão no treino de LLMs, onde os comprimentos variam muito.

2 · Modelo

A MLP: 2 → 32 → 32 → 2

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.rede = nn.Sequential(
            nn.Linear(2, 32),  nn.ReLU(),
            nn.Linear(32, 32), nn.ReLU(),
            nn.Linear(32, 2),
        )

    def forward(self, x):
        return self.rede(x)  # logits

ReLU = max(0, x). Sem ela, empilhar camadas lineares dá só outra camada linear.

A saída são 2 logits (notas cruas, uma por classe). Total: 96 + 1056 + 66 = 1218 parâmetros.

3 · Loss e otimizador

Medir o erro, corrigir os pesos

CrossEntropyLoss

Aplica softmax nos logits e pune a baixa probabilidade na classe certa: loss = −log p(classe certa).

logits→[ 2.0, −1.0 ] softmax→[ 0.95, 0.05 ] se y = 0→loss ≈ 0.05 ✓ se y = 1→loss ≈ 3.05 ✗

Por isso o modelo devolve logits sem softmax: a loss já faz essa parte.

Adam

criterio   = nn.CrossEntropyLoss()
otimizador = torch.optim.Adam(
    modelo.parameters(), lr=1e-2)

A cada step(), cada peso anda um pouco na direção que diminui a loss.

O lr (taxa de aprendizado) é o tamanho do passo. Alto demais: pula o mínimo. Baixo demais: demora muito.

4 · Loop de treino

O coração: 5 linhas, repetidas

for epoca in range(1, 21):
    modelo.train()
    for xb, yb in train_dl:
        logits = modelo(xb)          # (a)
        loss = criterio(logits, yb)  # (b)
        otimizador.zero_grad()       # (c)
        loss.backward()              # (d)
        otimizador.step()            # (e)

(c) vem antes de (d) porque o PyTorch acumula gradientes: sem zerar, somaria os do lote anterior.

20 épocas × 25 lotes = 500 voltas neste ciclo, ou seja, 500 atualizações de pesos.

5 · Uso

Avaliar: quantos acertos?

def avaliar(dl):
    modelo.eval()
    acertos, total = 0, 0
    with torch.no_grad():
        for xb, yb in dl:
            pred = modelo(xb).argmax(dim=1)
            acertos += (pred == yb).sum().item()
            total += yb.size(0)
    return acertos / total
[0.3, 2.1]→argmax→1→== y ?

eval()

Modo avaliação. Muda o comportamento de Dropout e BatchNorm (aqui não há, mas é o hábito certo).

no_grad()

Não guarda o grafo de gradientes: mais rápido e usa menos memória.

Compare acc treino com acc val. Se treino ≫ validação, a rede está decorando (overfitting).

Para estudar

Quebre o código de propósito

Tire os nn.ReLU()

A rede vira linear e não consegue desenhar um círculo. A acurácia empaca perto de 70%, que é o mesmo que chutar sempre “fora”.

Mude o lr

Com 1e-4 aprende muito devagar em 20 épocas. Com 1.0 a loss oscila ou explode.

Comente o zero_grad()

Os gradientes se somam lote após lote, os passos crescem e o treino fica instável.

Mude oculta para 4 ou 128

Com 4 neurônios a fronteira fica poligonal. Com 128 aprende rápido, mas tem mais capacidade para decorar.
